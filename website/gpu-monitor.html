What it helps explain

Low load does not mean empty memory.

A loaded model can keep GPU memory after a request ends. The monitor puts device activity, visible consumers and supported runtime information beside each other.

01 / ACTIVITY

See work and memory together.

Follow GPU load, temperature, memory and power where the driver exposes them. A rolling workload history separates computing, overhead, idle-held memory and unknown time.

02 / RESIDENCY

Find the visible owner.

Supported runtime APIs report model names. Process counters show visible memory consumers. When attribution is missing, the panel explains what is unknown.

03 / SYSTEM

Keep the wider system in view.

Check integrated graphics, NPU activity, CPU, RAM, disk and network beside the main GPU. Unavailable devices and counters are labelled clearly.

Practical questions

What to expect.

Does it support AMD and Intel GPUs?

On Windows, NVIDIA uses nvidia-smi. Other adapters use Windows graphics performance counters where available. Intel integrated graphics and compute-only NPUs have separate readings. Counter support varies by driver and device. AMD hardware has not yet been verified in this release.

What about multiple GPUs?

The Windows installer can select an NVIDIA GPU index for the main card. The panel shows one main GPU, one integrated GPU and one NPU. It does not provide a card for every adapter in a multi-GPU system. Model-to-device attribution also depends on the runtime information available.

Why can the model name be unknown?

A process can allocate memory without publishing a model ID through a supported API. The monitor can then show the largest visible process or state that memory is in use. That process is a memory consumer, not proof of a specific model. Idle-held memory also does not prove a memory leak.

How will updates work?

Click Updates in the Windows footer, or choose Check for updates from the right-click menu. The monitor checks the latest stable GitHub release only when requested. It asks before installing, checks package integrity, and preserves the panel position and sampling settings. Updates will become available after the public repository is connected.

What do Restart and Repair do?

Restart starts monitoring again. Repair restores the installed skin and launch tasks from the local copy. Repair does not download a new release. If local files are damaged, use the installer from a release package.

Does monitoring send my data to the cloud?

The monitor reads local hardware and supported local runtime APIs. It does not upload telemetry. Manual update checks contact GitHub. Model and process names can appear in the local panel and runtime files. A separate diagnostic command omits identifying strings for a report that you can review before sharing.
